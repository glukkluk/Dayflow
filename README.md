# Особистий розклад

Python 3.14+, Django, SQLite. Залежності керуються через `uv` і зафіксовані в `uv.lock`.

## Запуск

```sh
uv sync
uv run python app/manage.py migrate
uv run python app/manage.py runserver
```

## Реалізований етап: облікові записи

- Реєстрація за username, обов'язковим email та підтвердженим паролем.
- Стандартні перевірки й хешування паролів Django, вхід із підтримкою `next`, вихід через POST із CSRF.
- Автоматичне створення одного профілю через `post_save`; міграція додає профілі наявним користувачам.
- Редагування власного часового поясу, робочого дня й буфера (0–60 хв).
- Типові налаштування: Europe/Kyiv, 09:00–18:00, 10 хв.
- Валідація робочого часу у формі та обмеження в БД; часовий пояс активується на час запиту.
- Україномовні сторінки реєстрації, входу та профілю.

## Реалізований етап: категорії та базові події

- `/categories/`: список, створення, редагування та підтвердження видалення категорій.
- Назви категорій унікальні в межах власника; колір перевіряється як `#RRGGBB`.
- П'ять стандартних категорій створюються для нових користувачів. Наявні користувачі можуть додати категорії вручну.
- `/events/`: список із пошуком за назвою/описом та пагінацією по 20 записів.
- Створення, деталі, редагування й підтвердження видалення події; необов'язкова категорія та прапорець «Весь день».
- Час вводиться й відображається в поясі профілю, зберігається в UTC. Неоднозначний або неіснуючий локальний час відхиляється стандартною валідацією Django.
- Кінець строго пізніше за початок: перевірка форми й обмеження БД.
- Чужі записи за прямим URL повертають 404, вибір чужої категорії відхиляється.
- Видалення категорії скидає посилання подій у `NULL`; видалення виконується лише POST-запитом із CSRF.

Адреси категорій використовують числовий ID, стабільний при перейменуванні.
Повторення, нагадування, календар та перевірка конфліктів — наступні етапи; поточні події одноразові.

## Перевірка

```sh
uv run python app/manage.py check
uv run python app/manage.py test accounts planner
```

Для доступу до `/admin/` створіть адміністратора:

```sh
uv run python app/manage.py createsuperuser
```
